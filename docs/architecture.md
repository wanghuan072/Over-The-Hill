# Architecture and content maintenance

This is a Next.js 16.4 App Router site. `src/app` contains route boundaries and framework files. `src/page` contains full page implementations. All handwritten CSS is under `src/style`. `src/components` contains the two global layout components and content components shared across three or more business areas.

Internal links use ordinary anchors to perform full document navigation, as required by the supplied web-navigation rule. The matching Next.js lint rule is disabled intentionally. Filters, article anchors, native details elements update locally. There are no ads or analytics to initialize.

## Content

JSON collections under `src/data` are manually maintained. They are not outputs of a recurring fetch or publishing job. Query exports and publication filtering live in `src/lib/data/catalog.ts`; types live outside the data directory. Unknown detail slugs return 404. The source URL identifies evidence; `lastVerifiedAt` records checking, not a fictitious game update date. Article writing is original and does not copy competitor text.

Current content: three guides, 13 video-verified vehicle identities, 24 Wiki entries, two announced regions plus the Emerald Lake Demo area, six official-news summaries and a separate vehicle-system reference. This is 50 content/reference records and 25 public pages. Two named-landmark checklist records have no coordinates. Six species are developer-named, but the complete journal and spawn schedules are not assumed. Demo observations retain their build context and do not imply release testing.

`src/data/sources/sources.json` is the primary-reference registry. `sourceIds` on a record resolve named references through `src/lib/data/sources.ts`; section-level `sourceIds` provide local evidence links and must also appear at record level. Original URL fields remain supported for existing records. Source checking dates represent editorial review, not the publication date of the source. `evidenceNote` states the record’s limitations.

Sections support paragraphs, ordered steps, bullets and rectangular tables. Tables have captions and row/column headers with local overflow scrolling. Optional questions render native details elements without FAQPage markup. `summary` supplies a quick answer. Guides retain only beginner, winch and multiplayer pages. Vehicle systems are maintained in `src/data/vehicles/systems.json` and rendered on `/vehicles`; game-equipment entries appear on `/wiki/equipment`. Useful material from removed guides has been consolidated into those reference records. Search items include body text, headings, steps and table values; results still navigate with ordinary anchors. Map region selectors exclude area records, so Emerald Lake does not become a third launch region.

Add a checked record to its collection with a stable ID, unique slug, official or in-game source, version, checking date, image, alt text, body sections, SEO and related links. Use `confirmed` only when the claim is supported. Rebuild after content changes. Unverified and outdated records are excluded from public catalogs, search and sitemap. Source links for release regions are the official announcements feed; see the August 10, 2026 release announcement.

## Adding vehicles

`VehicleCatalog` renders vehicle facts directly on `/vehicles`; stock model art, all engine tiers, factory colours, distance liveries and unlock requirements are visible without disclosures. No vehicle, map or Wiki detail routes are published. `contentHref()` maps records to collection anchors; adding a future detail route requires explicitly changing this mapping, sitemap and audits. Catalog views prioritize text fields instead of assigning generic vehicle art to individual models. A locked menu listing is labelled as such, not as a playable Demo car.

`ContentRecord.facts` stores label, value, source ID and optional playback seconds. `FactTable` resolves the source and timestamp through `sourceMoment`. Sources may include video kind, publication date and duration. The content audit checks that every fact belongs to the record's source list and every timestamp fits the video duration. Price fields preserve vehicle/session context; conflicting recorded prices are not reconciled into a guessed launch value.

## Maps and removed tools

Maps remain on `/maps`, with the interactive atlas above the anchored region/area lists. `InteractiveMap` uses five existing local game topographic textures and 117 named points reconciled against game positions and an independent map. The atlas expansion adds 86 crates, 14 recovery pickups, 730 independently matched wildlife positions, 212 build-labelled meteorite spawns and 23 ordered challenge sequences (404 checkpoints). Rich records live in `src/data/maps/atlas.json`; curation and discrepancy handling are documented in `research/map-expanded-2026-10-19/verification.md`. Global species photos use one ID per species, area resets affect fixed stops only, and random meteorites have no completion ID. Dense spawn layers cluster at low zoom. Positions in `locations.json` are normalized to the individual area's image, not the country; world x/z cover a 4000-metre square and north-up y reverses z. Evidence and calibration live in `research/map-2026-10-19/verification.md`. Only compact display fields cross the client boundary. No third-party tiles, live API requests, routing service or player location are used. Pointer pan, cursor/pinch zoom, keyboard controls, search, filters and location selection remain local interactions. Versioned discovery IDs use localStorage with per-area reset and a storage failure message. Point data and atlas copy participate in persistent sitemap date fingerprints; provenance check dates do not. The Tools overview and its subroutes remain deleted, without redirects. No vehicle comparison, map detail routes or extra guide pages are added. Game equipment remains in the Wiki.

Screenshots are saved under ignored `test-results`.
